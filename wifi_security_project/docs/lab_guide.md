## Часть 1 — Теория: Стандарт AES

### 1.1 История и назначение

AES (Advanced Encryption Standard, FIPS 197) — симметричный блочный шифр, принятый NIST в 2001 году по итогам открытого конкурса. Победитель — алгоритм **Rijndael** бельгийских криптографов Joan Daemen и Vincent Rijmen.

**Параметры AES:**

| Параметр | Значение |
|---|---|
| Размер блока | 128 бит (16 байт) — фиксированный |
| Размер ключа | 128 / 192 / 256 бит |
| Количество раундов | 10 / 12 / 14 соответственно |

WPA2 использует **AES-128** (128-битный ключ, 10 раундов).

---

### 1.2 Внутреннее устройство AES

#### State (состояние)

AES работает с 4×4 матрицей байт, называемой **State**:

```
Plaintext bytes: b0 b1 b2 ... b15

State matrix (column-major):
┌──────────────────────────────┐
│  b0   b4   b8   b12          │
│  b1   b5   b9   b13          │
│  b2   b6   b10  b14          │
│  b3   b7   b11  b15          │
└──────────────────────────────┘
```

#### Четыре операции одного раунда

**1. SubBytes — Нелинейная подстановка**

Каждый байт заменяется значением из S-Box (таблица 16×16).
S-Box построен через мультипликативное обращение в GF(2⁸).

```python
# Пример: SubBytes для байта 0x53
state[0][0] = SBOX[state[0][0]]  # SBOX[0x53] = 0xED
```

*Назначение:* **Confusion** — нелинейное перемешивание, защита от линейного криптоанализа.

---

**2. ShiftRows — Циклический сдвиг строк**

```
До ShiftRows:          После ShiftRows:
┌─────────────────┐    ┌─────────────────┐
│ a0  a1  a2  a3  │    │ a0  a1  a2  a3  │  ← строка 0: без сдвига
│ b0  b1  b2  b3  │ →  │ b1  b2  b3  b0  │  ← строка 1: сдвиг на 1
│ c0  c1  c2  c3  │    │ c2  c3  c0  c1  │  ← строка 2: сдвиг на 2
│ d0  d1  d2  d3  │    │ d3  d0  d1  d2  │  ← строка 3: сдвиг на 3
└─────────────────┘    └─────────────────┘
```

*Назначение:* **Diffusion** — байты из разных столбцов перемешиваются между собой.

---

**3. MixColumns — Линейное смешение столбцов**

Каждый столбец рассматривается как многочлен над GF(2⁸) и умножается на фиксированную MDS-матрицу:

```
│ 2  3  1  1 │   │ col[0] │   │ result[0] │
│ 1  2  3  1 │ × │ col[1] │ = │ result[1] │
│ 1  1  2  3 │   │ col[2] │   │ result[2] │
│ 3  1  1  2 │   │ col[3] │   │ result[3] │
```

Умножение происходит в поле Галуа GF(2⁸) с неприводимым многочленом `x⁸ + x⁴ + x³ + x + 1`.

```python
def _gmul(a, b):
    """Умножение в GF(2^8) — сложение заменяется XOR"""
    result = 0
    for _ in range(8):
        if b & 1: result ^= a
        a = _xtime(a)  # умножение на 2
        b >>= 1
    return result
```

*Назначение:* **Diffusion** — один изменённый входной байт влияет на все 4 байта выходного столбца.

---

**4. AddRoundKey — Наложение ключа**

XOR каждого байта State с соответствующим байтом раундового ключа:

```python
state[r][c] ^= round_key[r][c]
```

*Назначение:* Единственная операция, которая вводит секретный ключ в шифрование.
Обратима тривиально: повторное XOR с тем же ключом восстанавливает исходное значение.

---

### 1.3 Ключевое расписание (Key Schedule)

AES-128 разворачивает 16-байтный ключ в 11 раундовых ключей по 16 байт каждый:

```
Раунд 0:  AES(K[0..15])         ← исходный ключ
Раунд 1:  AES(K[16..31])        ← производный
...
Раунд 10: AES(K[160..175])      ← финальный

Генерация каждого нового слова:
  Если i % 4 == 0:
    temp = SubWord(RotWord(W[i-1])) XOR RCON[i/4]
  Иначе:
    temp = W[i-1]
  W[i] = W[i-4] XOR temp
```

---

### 1.4 Структура полного шифрования AES-128

```
Plaintext (16 bytes)
       │
       ▼
AddRoundKey(RoundKey[0])
       │
  ┌────▼──────────────────────────────────┐
  │  Для раундов 1–9:                     │
  │    SubBytes → ShiftRows → MixColumns  │
  │           → AddRoundKey               │
  └───────────────────────────────────────┘
       │
  ┌────▼──────────────────────────────────┐
  │  Раунд 10 (финальный):                │
  │    SubBytes → ShiftRows               │
  │           → AddRoundKey               │  ← без MixColumns!
  └───────────────────────────────────────┘
       │
       ▼
Ciphertext (16 bytes)
```

---

### 1.5 Свойство лавины (Avalanche Effect)

Изменение **одного бита** в plaintext или ключе изменяет ~50% битов в ciphertext после всех раундов. Это фундаментальное требование к хорошему шифру.

## Часть 2 — Как AES используется в WPA2

### 2.1 CCMP (Counter with CBC-MAC Protocol)

WPA2 использует AES-128 в режиме **CCMP** — двойной режим:

```
┌──────────────────────────────────────────────────────────┐
│  CCMP = Counter Mode (CTR) + CBC-MAC                     │
│                                                          │
│  CTR-шифрование:                                         │
│    Keystream[i] = AES(TK, Nonce || Counter_i)            │
│    Ciphertext[i] = Plaintext[i] XOR Keystream[i]         │
│                                                          │
│  CBC-MAC аутентификация:                                 │
│    MAC_n = AES(TK, MAC_{n-1} XOR Block_n)                │
│    Итоговый MIC = первые 8 байт из CBC-MAC               │
└──────────────────────────────────────────────────────────┘
```

### 2.2 Иерархия ключей WPA2

```
WiFi Password + SSID
        │
        ▼  PBKDF2-HMAC-SHA1(password, SSID, iterations=4096, dklen=32)
        │
  PMK (Pairwise Master Key, 32 байта)
        │
        ▼  PRF-512(PMK, "Pairwise key expansion", MACs + Nonces)
        │
  PTK (Pairwise Transient Key, 64 байта)
        ├─► KCK [0:16]   ← Key Confirmation Key (для MIC в handshake)
        ├─► KEK [16:32]  ← Key Encryption Key (для шифрования GTK)
        └─► TK  [32:48]  ← Temporal Key (для AES-CCMP данных)
```

### 2.3 4-Way Handshake подробно

```
AP                              Client
│                                   │
│ ── M1: ANonce ──────────────────► │  AP отправляет случайное 32-байтное число
│                                   │
│                                   │  Client вычисляет:
│                                   │    PMK = PBKDF2(password, SSID)
│                                   │    PTK = PRF512(PMK, ANonce, SNonce, MACs)
│                                   │    MIC = HMAC-SHA1(KCK, EAPOL)[0:16]
│                                   │
│ ◄── M2: SNonce + MIC ────────── │  ← МЫ ЗАХВАТЫВАЕМ ЭТО!
│                                   │
│ Проверяет MIC                     │
│ ── M3: GTK + MIC ───────────────► │
│                                   │
│ ◄── M4: ACK ─────────────────── │
│                                   │
│         Оба используют TK для AES-CCMP
```

## Часть 3 — Почему AES не ломают напрямую

### 3.1 Известные атаки на AES

| Атака | Цель | Сложность | Практичность |
|---|---|---|---|
| Brute-force | AES-128 | 2¹²⁸ ≈ 3.4 × 10³⁸ | Невозможно (тепловая смерть вселенной) |
| Biclique attack | AES-128 | 2¹²⁶·¹ | Теоретически, не практично |
| Related-key attack | AES-192/256 | Требует контроля ключей | Не применимо к WPA2 |
| Side-channel | Реализация | Зависит от impl. | Только физический доступ |
| Square attack | Уменьшенный AES | 6 раундов | Не применимо к 10-раундовому AES |

**Вывод:** Ни одна из известных атак не даёт практического преимущества над brute-force для полного AES-128.

### 3.2 Реальная точка атаки — пароль

```
WPA2 система = AES (непробиваема) + Пароль (может быть слабым)

Атака идёт по слабому звену:

  Словарная атака:
    Для каждого слова из файла:
      PMK = PBKDF2(word, SSID)     ← ~2.4 мс на Python
      PTK = PRF512(PMK, ...)
      MIC = HMAC-SHA1(KCK, EAPOL)[0:16]
      Если MIC == captured_MIC → ПАРОЛЬ!
      
  Скорость на Python: ~300–800 паролей/секунду
  Скорость на GPU:    ~1,000,000+ паролей/секунду
```

### 3.3 PBKDF2 как защита от brute-force

**PBKDF2** (Password-Based Key Derivation Function 2):
- Применяет HMAC-SHA1 **4096 раз**
- Намеренно медленный — снижает скорость атаки
- Параметр `iterations` можно увеличить

```python
# Каждый вызов требует 4096 × SHA1 = ~дорого
PMK = hashlib.pbkdf2_hmac('sha1', password, ssid, 4096, 32)
```

Сравнение с MD5/SHA1 без PBKDF2:
- MD5 (одна итерация): 10,000,000,000 хешей/с на GPU
- PBKDF2-SHA1 (4096 iter): ~1,000,000 PMKs/с на GPU → в **10,000x** медленнее!

## Часть 6 — Итоги

| Характеристика | WEP | WPA | WPA2 |
|---|---|---|---|
| Шифр данных | RC4 (поточный) | RC4+TKIP | AES-CCMP |
| Длина ключа данных | 40/104 бит | 128 бит (TKIP) | 128 бит (AES) |
| MIC/ICV алгоритм | CRC-32 | HMAC-MD5 | HMAC-SHA1 |
| Атака на протокол | FMS, KoreK, PTW | Chop-chop, Beck-Tews | Только через пароль |
| Скорость атаки | Секунды | Минуты–часы | Зависит от пароля |
| Рекомендация | **ЗАПРЕЩЁН** | **Устарел** | Использовать |

**Главный вывод:**  
WPA2 криптографически стоек при условии использования **длинного случайного пароля** (≥12 символов из разных наборов). AES-128 не имеет практических структурных атак — единственная уязвимость системы — слабый пароль, перебираемый через PBKDF2.
